# 📚 Codex Paper Reader

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

**把本機文獻庫，變成可以與 Codex 一起思考的研究空間。**

專注於**本機文獻管理與閱讀**的輕量 Codex Skill。複製標題即可尋找 PDF，圍繞論文方法與證據展開討論，再將理解整理成個人化 HTML 筆記。搭配 Zotero 或慣用的 PDF 閱讀器使用，累積的來源與筆記也能繼續用於文件寫作和簡報製作。

📂 收集文獻 → 🔎 找到原文 → 💬 閱讀討論 → 📝 整理筆記 → 📽️ 分享理解

使用 Codex 開發與維護。

## 🚀 從一句話開始

**1. 📦 請 Codex 安裝 Skill**

```text
幫我安裝這個 Skill：https://github.com/hwang847/codex-paper-reader.git
```

**2. 📂 在 Codex 中開啟論文資料夾**

```text
使用 $literature-workflow，幫我設定這個資料夾的論文閱讀環境。
```

Codex 會檢查環境，依需求協助設定 Python 和 PDF 工具，並詢問相關的閱讀或歸檔偏好。它會保留既有檔案，將確認的偏好記入本機 `AGENTS.md`，完成後說明檔案位置、已就緒的功能與剩餘步驟。

**3. 💬 放入 PDF，從閱讀器複製標題**

新 PDF 放在工作區根目錄，保留 `2508.05002v1.pdf` 這類下載檔名即可：

```text
帶我閱讀這篇論文：<複製的標題>
從實作角度說明它的關鍵想法與方法流程。
現在根據我們的討論製作 HTML 筆記。
```

Codex 透過標題索引找到 PDF，並在文獻庫變動後於查找時更新索引。遇到掃描檔或標題歧義，可透過檔案路徑或標題修正來確認來源。

## 🔬 讓本機文獻真正用起來

| 功能 | 你能得到什麼 |
| --- | --- |
| 🔎 依標題找論文 | 用複製的標題、別名、arXiv ID 或檔名找到本機 PDF。 |
| 🗂️ 整理文獻庫 | 預覽依論文標題命名與分類的結果，再依你的要求或已儲存的偏好歸檔。 |
| 🔗 關聯多種來源 | 將 PDF、arXiv、DOI、程式碼與技術文件關聯到同一個閱讀對象。 |
| 💬 圍繞目標精讀 | 依你的關注點，討論關鍵貢獻、pipeline、實作、實驗或行文設計。 |
| 📝 留下自己的理解 | 依需求製作附來源連結與論文插圖截圖的 HTML 筆記，隨討論深入持續完善同一份筆記。 |
| 📑 比較一組文獻 | 確定文獻回顧的問題與範圍、比對證據，再與 Codex 一起完成綜合寫作。 |

### 🧩 它是怎麼做到的

- **本機標題索引。** Python 工具結合可用的 BibTeX 記錄、PDF 中繼資料與首頁文字，建立 `references/paper_index.jsonl`。正規化標題和別名支援精確與模糊比對，查找時會更新過期索引。
- **持續維護來源關聯。** `references/source_registry.jsonl` 將多個來源關聯到同一實體。歸檔時同步更新專案管理的來源路徑、BibTeX 來源註解、筆記連結與產生的文獻回顧引用路徑。
- **可核對的歸檔方案。** 可編輯的關鍵字規則與明確修正決定分類建議；移動檔案前提供預覽，同名檔案透過後綴保留。
- **有原文依據的討論。** 逐頁擷取的文字與原生 PDF 截圖，提供 Codex 可檢查、可引用的材料。指令碼負責可重複的檔案操作，Codex 負責解讀與寫作。

詳細用法見[工具說明](references/commands.md)。閱讀器負責顯示原文，Codex 陪你把原文讀懂。

## 🛠️ 在 Codex 中繼續創作

**文獻庫是起點，來源、筆記與討論可以接著成為下一項工作的素材。**

| 下一步 | 可以這樣告訴 Codex |
| --- | --- |
| ✍️ 潤飾研究筆記 | 「幫我把這份筆記寫得更清楚，保留我的判斷與來源連結。」 |
| 📄 撰寫與編輯文件 | 「將這些筆記整理成 related work 初稿」，或「為技術讀者修改這份報告」。 |
| 📽️ 製作簡報 | 「根據這些論文與筆記製作研究小組簡報，加入插圖、引用與講者備忘稿。」 |

這些後續任務由 Codex 的寫作能力，以及 [Codex 生態系](https://developers.openai.com/plugins)中可用的文件、簡報類 Skill、外掛與工具協同完成。本專案提供文獻工作流程與可重用的本機資料，特定檔案格式的編輯與匯出取決於你的工具環境；告訴 Codex 目標產出，它可以協助選擇和設定所需工具。

## 🎯 依你的研究方式客製化

```text
我正在寫文獻回顧，更關注每篇論文與既有工作的關係。
以論文寫作為目的閱讀時，要包括實驗設計與相關附錄。
請將這些偏好記在目前工作區的 AGENTS.md 中。
```

語言、閱讀深度、筆記風格、分類方式與後續工作流程，都可以隨使用逐步調整。Codex 維護你的本機偏好，通用 Skill 則保持跨專案重用。

既有文獻庫可以沿用原來的布局。新工作區通常使用 `papers/`、`notes/`（插圖放在 `notes/assets/`）、`references/` 與 `surveys/`。歸檔在 Codex 呼叫工作流程時執行，本機檔案始終作為主要副本。

## 🔌 連接你的工作工具

有需要時，再連接你使用的服務。以飛書/Lark 為例：

```text
幫我將這個工作區連接到飛書，用來歸檔選定的筆記。
在 GitHub 上找合適的 CLI，協助安裝，並在這個專案中統一管理設定。
```

Codex 會確認工具來源與相容性，經授權協助安裝及登入，將用法記錄在工作區的 `connectors/README.md` 或既有設定說明中。每次發布由你指定材料與目標位置；其他服務也能循此方式，結合可用工具擴充。

## ⚙️ 環境與安裝

- **宿主環境：** 採用標準 `SKILL.md`，以 Codex 為主要使用環境。其他支援 Skill、本機檔案與指令執行的 Agent 也可重用，設定方式由宿主決定。
- **本機工具：** Python 3.9+，搭配 PyMuPDF、Poppler 等工具擷取文字與渲染頁面，需要時可由 Codex 協助設定。
- **文獻歸檔：** 檔案移動使用 POSIX 介面，適用於 macOS/Linux；Windows 可透過 WSL 使用。目前驗證環境為 macOS。
