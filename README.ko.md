# Codex Paper Reader

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

**에이전트와 함께 논문을 읽고, PDF뿐 아니라 이해한 내용도 남기세요.**

논문 토론, 출처 관리, 맞춤형 HTML 노트 작성, 문헌 리뷰를 돕는 가벼운 Skill입니다. Zotero, 브라우저 등 평소 쓰는 PDF 뷰어와 함께 사용합니다. Codex로 개발하고 유지 관리합니다.

## 🚀 빠른 시작

**1. Codex에 설치 요청하기**

```text
이 Skill을 설치해 줘:
https://github.com/hwang847/codex-paper-reader.git
```

**2. Codex에서 논문 폴더 열기**

로컬 폴더를 하나 선택하고 다음과 같이 요청하세요.

```text
$literature-workflow를 사용해서 이 폴더에 논문 읽기 환경을 준비해 줘.
```

Codex가 환경을 확인하고, 필요하면 읽기 목표, 언어, 파일 정리 방식에 대해 간단히 묻습니다. 기존 파일과 지침은 유지하고 확인한 선호 사항을 로컬 `AGENTS.md`에 기록합니다. 설정 후에는 파일을 둘 위치, 사용할 수 있는 기능, 아직 준비되지 않은 항목, 읽기를 시작하는 방법을 안내합니다. Python과 PDF 도구 설정도 Codex의 도움을 받을 수 있어 미리 준비할 필요가 없습니다. 선호 사항은 나중에 대화로 바꿀 수 있습니다.

**3. PDF를 넣고 대화 시작하기**

`2508.05002v1.pdf`처럼 다운로드한 파일명을 그대로 사용해도 됩니다. 뷰어에서 논문 제목을 복사하세요.

```text
이 논문을 함께 읽어 줘: <복사한 제목>
직접 구현할 수 있도록 방법의 흐름을 설명해 줘.
지금까지의 논의를 바탕으로 HTML 노트를 만들어 줘.
```

Codex가 제목 색인으로 해당 로컬 PDF를 찾습니다. 파일명을 직접 바꾸거나 색인을 관리할 필요가 없습니다. 스캔본, 특수한 레이아웃, 구분하기 어려운 제목은 경로를 지정하거나 제목을 수정해야 할 수 있습니다.

## ✨ 어떤 도움을 받을 수 있나요?

| 요청 | Codex와 Skill이 돕는 일 |
| --- | --- |
| “내 연구 주제와 연결해서 설명해 줘.” | 원하는 깊이로 읽고 번역하며 토론합니다. 필요하면 실험과 부록도 자세히 다룹니다. |
| “논의해서 정리한 내용을 남겨 줘.” | 출처 링크와 논문 그림 스크린샷을 담은 간결한 맞춤형 HTML 노트를 작성합니다. 이해가 달라지면 같은 노트를 갱신합니다. |
| “새로 추가한 논문을 정리해 줘.” | 제목 기반 파일명과 분류 결과를 미리 보여 준 뒤 정리합니다. 중복 파일을 덮어쓰지 않고 관리 대상 링크도 갱신합니다. |
| “이 코드 저장소는 저 논문의 것이야.” | PDF, arXiv, DOI, 코드, 기술 문서를 하나의 읽기 대상에 연결된 출처로 관리합니다. |
| “이 논문들을 비교해서 문헌 리뷰를 도와줘.” | 선택한 문헌 범위를 유지하고 근거를 비교하며, 요청하면 리뷰 본문을 작성합니다. |

노트는 요청할 때 만들며, 답변마다 새로 생성하지 않습니다. 자동 정리는 선택 사항이며 Codex가 워크플로를 실행할 때 작동합니다. 백그라운드 감시는 하지 않습니다. 로컬 파일이 항상 기준이 되는 사본입니다.

## 🎯 나에게 맞게 사용하기

원하는 방식을 Codex에 말해 주세요.

```text
문헌 리뷰를 쓰고 있으니 각 논문이 선행 연구와 어떤 관계에 있는지에 집중해 줘.
논문 작성을 위해 읽을 때는 평가 설계와 관련 부록도 포함해 줘.
이 선호 사항을 현재 작업 공간의 AGENTS.md에 기록해 줘.
```

언어, 노트 스타일, 분류 방식, 읽기 흐름을 대화로 조정할 수 있습니다. 기존 문헌 폴더를 새로운 구조로 옮길 필요는 없습니다.

새 작업 공간은 보통 `papers/`, `notes/`(이미지는 `notes/assets/`), `references/`, `surveys/`를 사용합니다. 새 PDF는 작업 공간 루트에 넣고 Codex에 정리를 요청하거나 자동 정리 선호 사항을 설정하세요.

## 🔌 외부 서비스 연결 (선택 사항)

연구 결과를 다른 서비스에서도 활용하고 싶다면 Codex에 말해 주세요. 예를 들면:

```text
선택한 노트를 보관할 수 있도록 이 작업 공간을 Feishu에 연결해 줘.
GitHub에서 적절한 CLI를 찾아 설치를 돕고, 이 프로젝트에서 설정을 함께 관리해 줘.
```

Codex가 도구의 출처와 호환성을 확인하고, 승인을 받아 설치와 로그인을 돕습니다. 사용법은 작업 공간의 `connectors/README.md` 또는 기존 설정 문서에 기록합니다. Feishu/Lark는 한 가지 예시이며, 다른 서비스도 사용 가능한 도구에 따라 추가할 수 있습니다. 미리 설치하거나 자동으로 동기화하지 않으며, 논문 읽기와 노트 작성에는 외부 연결이 필요하지 않습니다.

## 기능 범위와 호환성

Skill은 작은 워크플로와 신뢰할 수 있는 로컬 도구를 제공합니다. **추론과 글쓰기는 호스트 에이전트가 담당합니다.** PDF 뷰어, 무인 연구 서비스, 범용 챗봇은 아닙니다. 평소 쓰는 뷰어를 계속 사용하면서 연구할 자료를 선택하세요. Skill 자체에는 모델 API 키나 전용 서버가 필요하지 않습니다.

표준 `SKILL.md` 형식을 사용하며 보조 스크립트에는 Python 3.9+가 필요합니다. 주 사용 환경은 Codex입니다. 다른 Skill 지원 에이전트도 로컬 파일과 명령 실행을 지원하면 재사용할 수 있습니다. 설치 방식과 도구 권한은 호스트에 따라 다릅니다. PDF 추출과 렌더링에 필요한 선택 도구는 필요할 때 Codex의 도움을 받아 설치할 수 있습니다.

안전한 파일 이동에는 POSIX API를 사용합니다. macOS/Linux 또는 Windows의 WSL을 이용하세요. 네이티브 Windows 환경의 파일 정리는 지원하지 않습니다.

mkdir -p ~/.agents/skills
