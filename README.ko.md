# 📚 Codex Paper Reader

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

**내 논문 폴더를 Codex와 함께 생각하는 연구 공간으로.**

**로컬 문헌 관리와 논문 읽기**에 집중한 가벼운 Codex Skill입니다. 복사한 제목으로 PDF를 찾고, 방법과 근거를 토론하고, 이해한 내용을 맞춤형 HTML 노트로 정리합니다. Zotero나 평소 쓰는 PDF 뷰어와 함께 사용하며, 쌓인 자료와 노트를 문서 작성과 발표 자료 제작에도 활용할 수 있습니다.

📂 수집 → 🔎 검색 → 💬 읽기와 토론 → 📝 노트 정리 → 📽️ 공유

Codex로 개발하고 유지 관리합니다.

## 🚀 대화로 시작하기

**1. 📦 Codex에 Skill 설치 요청하기**

```text
이 Skill을 설치해 줘:
https://github.com/hwang847/codex-paper-reader.git
```

**2. 📂 Codex에서 논문 폴더 열기**

```text
$literature-workflow를 사용해서 이 폴더에 논문 읽기 환경을 준비해 줘.
```

Codex가 환경을 확인하고, 필요에 따라 Python과 PDF 도구 설정을 도우며, 읽기와 파일 정리 방식에 대한 선호를 묻습니다. 기존 파일을 유지하면서 확인한 선호 사항을 로컬 `AGENTS.md`에 기록합니다. 설정 후에는 파일 위치, 사용할 수 있는 기능, 남은 단계를 안내합니다.

**3. 💬 PDF를 넣고 뷰어에서 제목 복사하기**

새 PDF는 작업 공간 루트에 넣으세요. `2508.05002v1.pdf` 같은 다운로드 파일명을 그대로 사용할 수 있습니다.

```text
이 논문을 함께 읽어 줘: <복사한 제목>
직접 구현할 수 있도록 핵심 아이디어와 방법의 흐름을 설명해 줘.
지금까지의 논의를 바탕으로 HTML 노트를 만들어 줘.
```

Codex가 제목 색인으로 PDF를 찾고, 문헌이 추가되거나 변경되면 검색할 때 색인을 갱신합니다. 스캔본이나 구분하기 어려운 제목은 파일 경로를 지정하거나 제목을 수정해 출처를 확인할 수 있습니다.

## 🔬 논문 폴더를 활용 가능한 문헌 라이브러리로

| 기능 | 얻을 수 있는 것 |
| --- | --- |
| 🔎 제목으로 논문 찾기 | 복사한 제목, 별칭, arXiv ID, 파일명으로 로컬 PDF를 찾습니다. |
| 🗂️ 문헌 정리 | 제목 기반 파일명과 분류 결과를 미리 확인하고, 요청이나 저장된 선호에 따라 정리합니다. |
| 🔗 여러 출처 연결 | PDF, arXiv, DOI, 코드, 기술 문서를 하나의 읽기 대상에 연결합니다. |
| 💬 목적에 맞게 정독 | 기여점, 파이프라인, 구현, 실험, 논문 구성 중 관심 있는 부분을 원하는 깊이로 토론합니다. |
| 📝 나만의 이해 기록 | 요청하면 출처 링크와 논문 그림 스크린샷을 포함한 HTML 노트를 만들고, 토론이 깊어질수록 같은 노트를 다듬습니다. |
| 📑 선택한 문헌 비교 | 리뷰의 질문과 문헌 범위를 정하고, 근거를 비교하며, Codex와 종합적인 글을 작성합니다. |

### 🧩 작동 방식

- **로컬 제목 색인.** Python 도구가 사용 가능한 BibTeX 기록, PDF 메타데이터, 첫 페이지 텍스트를 바탕으로 `references/paper_index.jsonl`을 만듭니다. 정규화한 제목과 별칭으로 정확 일치 및 유사도 검색을 지원하며, 검색 시 오래된 색인을 갱신합니다.
- **출처 관계 유지.** `references/source_registry.jsonl`이 여러 출처를 하나의 대상에 연결합니다. 파일 정리 시 관리 대상 출처 경로, BibTeX 출처 주석, 노트 링크, 생성된 리뷰 자료의 참조 경로도 갱신합니다.
- **검토 가능한 정리 과정.** 수정 가능한 키워드 규칙과 개별 지정값으로 분류를 제안합니다. 파일 이동 전 미리보기를 제공하고, 같은 이름의 PDF는 접미사를 붙여 보존합니다.
- **원문에 근거한 토론.** 페이지별 텍스트와 PDF 스크린샷을 Codex가 확인하고 인용할 자료로 사용합니다. 반복적인 파일 작업은 스크립트가, 해석과 글쓰기는 Codex가 담당합니다.

자세한 사용법은 [명령어 안내](references/commands.md)를 참고하세요. 뷰어로 원문을 보면서 Codex와 이해를 넓혀 갈 수 있습니다.

## 🛠️ Codex에서 다음 작업으로 이어가기

**문헌 라이브러리는 출발점입니다. 자료, 노트, 토론을 다음 작업의 재료로 활용하세요.**

| 다음 작업 | Codex에 요청하는 예 |
| --- | --- |
| ✍️ 연구 노트 다듬기 | “내 판단과 출처 링크를 유지하면서 이 노트를 더 명확하게 다듬어 줘.” |
| 📄 문서 작성 및 편집 | “이 노트들을 관련 연구 초안으로 정리해 줘.” “이 보고서를 기술 독자에 맞게 수정해 줘.” |
| 📽️ 발표 자료 만들기 | “이 논문과 노트를 바탕으로 그림, 인용, 발표자 노트가 포함된 연구실 미팅 슬라이드를 만들어 줘.” |

이런 후속 작업은 Codex의 글쓰기 능력과 [Codex 생태계](https://developers.openai.com/plugins)에서 사용 가능한 문서·프레젠테이션 Skill, 플러그인, 도구를 조합해 진행합니다. 이 프로젝트는 문헌 워크플로와 재사용할 수 있는 로컬 자료를 제공합니다. 파일 형식별 편집과 내보내기는 환경에 갖춰진 도구에 따라 달라지므로, 원하는 결과물을 알려 주고 Codex에 도구 선택과 설정을 요청하세요.

## 🎯 내 연구 방식에 맞추기

```text
문헌 리뷰를 쓰고 있으니 각 논문과 선행 연구의 관계에 집중해 줘.
논문 작성을 위해 읽을 때는 평가 설계와 관련 부록도 포함해 줘.
이 선호 사항을 현재 작업 공간의 AGENTS.md에 기록해 줘.
```

언어, 읽기 깊이, 노트 스타일, 분류 방식, 후속 워크플로는 대화를 통해 점차 조정할 수 있습니다. Codex가 로컬 선호 사항을 관리하고, 공통 Skill은 여러 프로젝트에서 재사용할 수 있습니다.

기존 문헌 폴더는 현재 구조를 유지할 수 있습니다. 새 작업 공간은 보통 `papers/`, `notes/`(그림은 `notes/assets/`), `references/`, `surveys/`를 사용합니다. 파일 정리는 Codex가 워크플로를 호출할 때 실행되며, 로컬 파일이 기준이 되는 사본입니다.

## 🔌 업무 도구와 연결하기

필요에 따라 사용 중인 서비스를 연결하세요. Feishu/Lark를 예로 들면:

```text
선택한 노트를 보관할 수 있도록 이 작업 공간을 Feishu에 연결해 줘.
GitHub에서 적절한 CLI를 찾아 설치를 돕고, 이 프로젝트에서 설정을 함께 관리해 줘.
```

Codex가 도구의 출처와 호환성을 확인하고, 승인을 받아 설치와 로그인을 돕습니다. 사용법은 작업 공간의 `connectors/README.md` 또는 기존 설정 문서에 기록합니다. 게시할 자료와 대상 위치는 요청마다 지정하세요. 다른 서비스도 사용 가능한 도구를 활용해 같은 방식으로 추가할 수 있습니다.

## ⚙️ 환경과 설치

- **호스트:** 표준 `SKILL.md` 형식이며 Codex를 주 사용 환경으로 삼습니다. 다른 Skill 지원 에이전트도 로컬 파일과 명령 실행 기능이 있으면 재사용할 수 있습니다. 설정 방식은 호스트에 따라 다릅니다.
- **로컬 도구:** Python 3.9+와 PyMuPDF, Poppler 같은 텍스트 추출·렌더링 도구를 사용합니다. 필요할 때 Codex의 도움을 받아 설정할 수 있습니다.
- **문헌 정리:** 파일 이동은 POSIX API를 사용합니다. macOS/Linux 또는 Windows의 WSL에서 이용할 수 있으며, 현재 검증 환경은 macOS입니다.
