# 📚 Codex Paper Reader

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

**把本地文献库，变成可以与 Codex 一起思考的研究空间。**

一个专注于**本地文献管理与阅读**的轻量 Codex Skill。复制标题即可查找 PDF，围绕论文方法与证据展开讨论，再将理解整理成个性化 HTML 笔记。与 Zotero 或你惯用的 PDF 阅读器配合使用，积累的来源与笔记还可以继续用于文档写作和演示材料制作。

📂 收集文献 → 🔎 定位原文 → 💬 阅读讨论 → 📝 沉淀笔记 → 📽️ 整理分享

使用 Codex 开发并维护。

## 🚀 从一句话开始

**1. 📦 请 Codex 安装 Skill**

```text
帮我安装这个 Skill：https://github.com/hwang847/codex-paper-reader.git
```

**2. 📂 在 Codex 中打开论文文件夹**

```text
使用 $literature-workflow，帮我配置这个文件夹的论文阅读工作环境。
```

Codex 会检查环境，按需协助配置 Python 和 PDF 工具，并询问相关的阅读或归档偏好。它会保留已有文件，将确认的偏好记入本地 `AGENTS.md`，完成后告诉你文件位置、已就绪的能力和剩余步骤。

**3. 💬 放入 PDF，从阅读器复制标题**

新 PDF 放在工作区根目录，保留 `2508.05002v1.pdf` 这样的下载文件名即可：

```text
带我阅读这篇论文：<复制的标题>
从实现角度讲清楚它的关键想法和方法流程。
现在根据我们的讨论生成 HTML 笔记。
```

Codex 通过标题索引定位 PDF，并在文献库变化后于查找时刷新索引。遇到扫描件或标题歧义，可以用文件路径或标题修正来确认来源。

## 🔬 让本地文献真正用起来

| 能力 | 你能得到什么 |
| --- | --- |
| 🔎 按标题找论文 | 用复制的标题、别名、arXiv ID 或文件名定位本地 PDF。 |
| 🗂️ 整理文献库 | 预览按论文标题命名和分类的结果，再按你的要求或已保存的偏好执行归档。 |
| 🔗 关联多种来源 | 将 PDF、arXiv、DOI、代码与技术文档关联到同一个阅读对象。 |
| 💬 围绕目标精读 | 根据你的关注点，讨论关键贡献、pipeline、实现、实验或行文设计。 |
| 📝 留下自己的理解 | 按需生成带来源链接与论文插图截图的 HTML 笔记，随讨论深入持续完善同一份笔记。 |
| 📑 对照一组文献 | 确定综述问题与文献范围，对照证据，再与 Codex 一起完成综合写作。 |

### 🧩 它是怎样做到的

- **本地标题索引。** Python 工具结合可用的 BibTeX 记录、PDF 元数据与首页文本，建立 `references/paper_index.jsonl`。归一化标题和别名支持精确与模糊匹配，查找时会刷新过期索引。
- **持续维护来源关联。** `references/source_registry.jsonl` 将多个来源关联到同一实体。归档时同步更新项目管理的来源路径、BibTeX 来源注释、笔记链接和生成的综述引用路径。
- **可核对的归档方案。** 可编辑的关键词规则与显式修正决定分类建议；文件移动前提供预览，重名文件通过后缀保留。
- **带原文依据的讨论。** 按页提取的文本与原生 PDF 截图，为 Codex 提供可检查、可引用的材料。脚本负责可重复的文件操作，Codex 负责解读与写作。

具体用法见[工具说明](references/commands.md)。阅读器负责展示原文，Codex 陪你把原文读懂。

## 🛠️ 在 Codex 中继续创作

**文献库是起点，来源、笔记与讨论可以接着成为下一项工作的素材。**

| 下一步 | 可以这样告诉 Codex |
| --- | --- |
| ✍️ 润色研究手记 | “帮我把这份笔记写得更清晰，保留我的判断和来源链接。” |
| 📄 撰写与编辑文档 | “将这些笔记整理成 related work 初稿”，或“为技术读者修改这份报告”。 |
| 📽️ 制作演示材料 | “根据这些论文和笔记制作组会演示，加入插图、引用与演讲备注。” |

这些后续任务由 Codex 的写作能力，以及 [Codex 生态](https://developers.openai.com/plugins)中可用的文档、演示类 Skill、插件和工具协同完成。本项目提供文献工作流与可复用的本地资料，具体文件格式的编辑和导出取决于你的工具环境；告诉 Codex 目标产物，它可以协助选择和配置所需工具。

## 🎯 按你的研究方式定制

```text
我正在写综述，更关注每篇论文与已有工作的关系。
以论文写作为目的阅读时，要包括实验设计和相关附录。
请将这些偏好记在当前工作区的 AGENTS.md 中。
```

语言、阅读深度、笔记风格、分类方式与后续工作流，都可以随使用逐步调整。Codex 维护你的本地偏好，通用 Skill 则保持跨项目复用。

已有文献库可以沿用原来的布局。新工作区通常使用 `papers/`、`notes/`（插图放在 `notes/assets/`）、`references/` 和 `surveys/`。归档在 Codex 调用工作流时执行，本地文件始终作为主要副本。

## 🔌 接入你的工作工具

有需要时，再连接你使用的服务。以飞书/Lark 为例：

```text
帮我给这个工作区接入飞书，用来归档选定的笔记。
在 GitHub 上找合适的 CLI，协助安装，并在这个项目中统一管理配置。
```

Codex 会核实工具来源与兼容性，经授权协助安装和登录，将用法记录在工作区的 `connectors/README.md` 或已有配置说明中。每次发布由你指定材料和目标位置；其他服务也可按这个方式，结合可用工具扩展。

## ⚙️ 环境与安装

- **宿主环境：** 采用标准 `SKILL.md`，以 Codex 为主要使用环境。其他支持 Skill、本地文件与命令执行的 Agent 也可复用，配置方式由宿主决定。
- **本地工具：** Python 3.9+，配合 PyMuPDF、Poppler 等工具提取文本与渲染页面，需要时可由 Codex 协助配置。
- **文献归档：** 文件移动使用 POSIX 接口，适用于 macOS/Linux；Windows 可通过 WSL 使用。当前验证环境为 macOS。
