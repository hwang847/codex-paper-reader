# 📚 Codex Paper Reader

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

**手元の論文フォルダーを、Codex と考える研究の場に。**

**ローカルでの文献管理と論文の読解**に特化した、軽量な Codex Skill です。コピーしたタイトルから PDF を探し、手法や根拠を議論し、自分の関心に沿った HTML ノートを残せます。Zotero など普段の PDF リーダーと併用し、蓄積した資料とノートを文書やプレゼンテーションの作成にも活用できます。

📂 集める → 🔎 探す → 💬 読んで議論する → 📝 ノートに残す → 📽️ 伝える

Codex を使って開発・保守しています。

## 🚀 対話から始める

**1. 📦 Skill のインストールを頼む**

```text
この Skill をインストールして：
https://github.com/hwang847/codex-paper-reader.git
```

**2. 📂 論文フォルダーを Codex で開く**

```text
$literature-workflow を使って、このフォルダーに論文を読むための環境を整えて。
```

Codex が環境を確認し、必要に応じて Python や PDF ツールの準備を手伝い、読む目的や整理方法の好みを尋ねます。既存のファイルを保持し、確認した好みをローカルの `AGENTS.md` に記録します。設定後は、保存先、使える機能、残っている手順を案内します。

**3. 💬 PDF を入れて、リーダーからタイトルをコピーする**

新しい PDF はワークスペースのルートに置きます。`2508.05002v1.pdf` のようなダウンロード時のファイル名で構いません。

```text
この論文を一緒に読んで：<コピーしたタイトル>
自分で実装できるように、中心となるアイデアと手法の流れを説明して。
ここまでの議論を基に HTML ノートを作って。
```

Codex がタイトル索引から PDF を探し、文献の追加や変更があれば検索時に索引を更新します。スキャン文書や紛らわしいタイトルでは、パスの指定やタイトルの修正で資料を特定できます。

## 🔬 論文フォルダーを使える文献ライブラリーに

| 機能 | できること |
| --- | --- |
| 🔎 タイトルで探す | コピーしたタイトル、別名、arXiv ID、ファイル名からローカル PDF を見つけます。 |
| 🗂️ 文献を整理する | タイトルに基づく命名と分類をプレビューし、依頼や保存済みの設定に応じて整理します。 |
| 🔗 出典を結び付ける | PDF、arXiv、DOI、コード、技術文書を、一つの読解対象に関連付けます。 |
| 💬 目的に合わせて読む | 貢献、パイプライン、実装、実験、論文構成を、関心に合わせた深さで議論します。 |
| 📝 理解を残す | 依頼に応じて、出典リンクや論文の図のスクリーンショットを含む HTML ノートを作成。議論が深まったら同じノートを更新します。 |
| 📑 複数の文献を比較する | レビューの問いと対象文献を定め、根拠を比較し、Codex と総合的な考察をまとめます。 |

### 🧩 仕組み

- **ローカルのタイトル索引。** Python ツールが、利用可能な BibTeX、PDF メタデータ、先頭ページのテキストを基に `references/paper_index.jsonl` を作成します。正規化したタイトルと別名で完全一致・あいまい検索を行い、古い索引は検索時に更新します。
- **出典のつながりを維持。** `references/source_registry.jsonl` が複数の出典を一つの対象に関連付けます。整理時には、管理対象の出典パス、BibTeX の出典コメント、ノートのリンク、生成したレビュー資料の参照パスも更新します。
- **確認できる整理手順。** 編集可能なキーワード規則と個別の修正から分類を提案します。移動前にプレビューし、同名の PDF は接尾辞を付けて保持します。
- **原文に基づく議論。** ページ単位のテキストと PDF のスクリーンショットが、確認・引用できる材料になります。繰り返し行うファイル操作はスクリプトが、解釈と執筆は Codex が担当します。

詳しくは[コマンドの説明](references/commands.md)を参照してください。リーダーで原文を見ながら、Codex と理解を深められます。

## 🛠️ Codex で次の成果物へ

**文献ライブラリーは出発点です。資料、ノート、議論を次の作業につなげられます。**

| 次の作業 | Codex への依頼例 |
| --- | --- |
| ✍️ 研究ノートを磨く | 「私の考察と出典リンクを残しながら、このノートを読みやすく整えて」 |
| 📄 文書を執筆・編集する | 「このノートを関連研究の草稿にして」「この報告書を技術者向けに推敲して」 |
| 📽️ 発表資料を作る | 「この論文とノートを使い、図・引用・発表者ノートを含む研究室ミーティング用のスライドを作って」 |

こうした作業には、Codex の執筆能力と、[Codex エコシステム](https://developers.openai.com/plugins)で利用できる文書・プレゼンテーション向け Skill、プラグイン、ツールを組み合わせます。本プロジェクトは文献ワークフローと再利用できるローカル資料を提供します。ファイル形式ごとの編集や書き出しは環境内のツールに応じて行うため、作りたい成果物を伝えて、適切なツールの選定・設定を Codex に相談できます。

## 🎯 自分の研究に合わせる

```text
文献レビューを書いているので、各論文と先行研究の関係を重視して。
論文執筆のために読むときは、評価設計と関連する付録も扱って。
この好みをワークスペースの AGENTS.md に記録して。
```

言語、読む深さ、ノートのスタイル、分類、後続の作業は、対話を重ねながら調整できます。Codex がローカルの好みを管理し、共通の Skill は複数のプロジェクトで再利用できます。

既存の文献フォルダーは今の構成を使えます。新しいワークスペースでは通常、`papers/`、`notes/`（図は `notes/assets/`）、`references/`、`surveys/` を使います。ファイル整理は Codex がワークフローを呼び出すときに実行され、ローカルファイルが主となるコピーです。

## 🔌 仕事で使うサービスと連携する

用途に応じて、利用中のサービスを追加できます。Feishu/Lark の例：

```text
選んだノートを保存できるように、このワークスペースを Feishu と連携させて。
GitHub で適切な CLI を探して導入を手伝い、設定をこのプロジェクトでまとめて管理して。
```

Codex が提供元と互換性を確認し、許可を得てインストールやログインを支援します。使い方はワークスペースの `connectors/README.md` または既存の設定メモに記録します。公開する資料と保存先は依頼ごとに指定します。他のサービスも、利用できるツールに応じて同様に追加できます。

## ⚙️ 動作環境とインストール

- **ホスト：** 標準の `SKILL.md` 形式で、主な対象は Codex です。他の Skill 対応エージェントも、ローカルファイルとコマンド実行を利用できれば再利用できます。設定方法はホストによります。
- **ローカルツール：** Python 3.9+ と、テキスト抽出・描画用の PyMuPDF や Poppler などを使います。必要になった時点で Codex が導入を支援できます。
- **ファイル整理：** POSIX API を利用します。macOS/Linux、または Windows の WSL が対象です。現在の検証環境は macOS です。
